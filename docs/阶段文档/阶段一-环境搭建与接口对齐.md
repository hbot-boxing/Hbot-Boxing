## 1. 目标与验收

### 1.1 目标

建立一套能完成以下三件事的本地环境：

1. 用官方评测镜像完成一次 `--validate`；
2. 把仿真给出的 `obs [1,1097]` 正确切分并转成模型输入张量；
3. 把模型输出 `target_pose [1,225]` 正确还原成接口要求的动作格式。

### 1.2 验收标准

| 项 | 通过标准 |
| --- | --- |
| 镜像 | `docker pull` 成功，`run.sh --validate` 能加载 dummy ONNX |
| 观测解析 | 解析出的字段总数 = 1097，且各字段值与仿真状态自洽 |
| 动作还原 | 输出张量形状恰为 `[1,225]`，值域在 HoloMotion 接受范围内 |
| 闭环 | 本地 dummy 策略能完整跑完一局 60s 对战并生成 replay |

## 2. 工程目录规划

建议在仓库根目录建立如下结构（与官方 `holoboxing/` 保持分离，避免污染官方代码）：

```
H-Bot/
├── docs/                          # 已有文档
├── holoboxing/                    # 官方仓库（只读，勿改）
├── src/
│   ├── adapters/
│   │   ├── obs_adapter.py         # obs[1097] 解析 -> 模型输入
│   │   └── action_adapter.py      # 模型输出 -> target_pose[225]
│   ├── models/                    # 网络定义
│   ├── train/                     # 训练入口
│   ├── export/                    # ONNX 导出脚本
│   └── eval/                      # 本地评测封装
├── models/                        # 导出的 .onnx
├── outputs/                       # 训练日志、回放、评测产物
└── scripts/
    ├── setup_env.sh
    ├── run_validate.sh
    └── run_match.sh
```

**原则**：官方 `holoboxing/` 目录只读；所有自研代码放在 `src/`，通过脚本调用官方入口。

## 4. 接口对齐

接口对齐是本阶段的核心风险点。架构文档第 4 章给出的是**规格边界**（1097 / 225），具体字段顺序与坐标系必须以官方接口文档为准。

### 4.1 观测 `obs [1,1097]`

**对齐方法**（不靠猜，靠打印）：

1. 在官方 Server 入口处打印 `obs` 的 shape、dtype、前若干维数值；
2. 让仿真处于可控初始态（静止站立、无对手动作），记录数值；
3. 人为改变单一条件（如前进 0.2m、抬右手），观察哪一段数值发生变化；
4. 用「单变量扰动法」逐段锁定字段区间。

**字段分组（架构文档口径）**：

| 组 | 内容 | 对齐要点 |
| --- | --- | --- |
| 自身状态 | 骨盆/双腕/双踝等关键点位姿、速度、历史 | 确认是否为世界系还是躯干系；历史帧数与排列顺序 |
| 对手信息 | 对手关键点相对自身位置 | 确认「相对」的参考点（骨盆还是躯干） |
| 比赛信息 | 剩余时间、分差 | 确认归一化区间（0~1 还是秒数） |

**产出**：`src/adapters/obs_adapter.py` 中的字段偏移表：

```python
OBS_FIELDS = {
    "self_pelvis_pos":   (0, 3),
    "self_pelvis_quat":  (3, 4),
    # ... 逐段补全，总和必须等于 1097
}
```

> 校验：所有切片区间长度求和 = 1097，否则说明分组有误或存在未解析的 padding 段。

### 4.2 动作 `target_pose [1,225]`

**对齐方法**（反向验证）：

1. 构造「全零」「全当前位姿」「小步偏移」三类输出，观察机器人在仿真中的反应；
2. 全零若导致机器人塌陷，说明该字段是绝对位姿而非残差；
3. 只改某一段数值，观察是哪个关节/关键点动，从而锁定排列顺序。

**输出结构**：按架构文档推断为 `T 帧 × K 关键点 × D 维度` 的组合（如 15×15×1），实际以官方文档为准。需要确认：

| 待确认项 | 影响 |
| --- | --- |
| 时间窗口 T 帧 | 决定输出频率与闭环延迟 |
| 关键点数量与顺序 | 决定输出的语义正确性 |
| 位姿表示（位置/四元数/欧拉角） | 决定值域与后处理方式 |
| 坐标系（世界/躯干） | 决定是否需要变换 |

**产出**：`src/adapters/action_adapter.py` 中的输出映射表与值域裁剪逻辑。

## 5. 适配层代码骨架

### 5.1 观测适配器

```python
import numpy as np

class ObsAdapter:
    def __init__(self, stats=None):
        self.stats = stats or {}   # 官方均值/方差，缺省不归一化

    def to_model_input(self, obs: np.ndarray) -> np.ndarray:
        assert obs.shape == (1, 1097), obs.shape
        assert obs.dtype == np.float32, obs.dtype
        x = obs.copy()
        for name, (lo, hi) in OBS_FIELDS.items():
            if name in self.stats:
                mean, std = self.stats[name]
                x[:, lo:hi] = (x[:, lo:hi] - mean) / (std + 1e-6)
        return x
```

### 5.2 动作适配器

```python
class ActionAdapter:
    def __init__(self, pose_min, pose_max, smooth_alpha=0.2):
        self.pose_min = pose_min      # 由官方文档给出
        self.pose_max = pose_max
        self.alpha = smooth_alpha
        self._prev = None

    def to_target_pose(self, y: np.ndarray) -> np.ndarray:
        assert y.shape == (1, 225), y.shape
        y = np.clip(y, self.pose_min, self.pose_max)
        if self._prev is not None:
            y = self.alpha * y + (1 - self.alpha) * self._prev   # 平滑，防突跳
        self._prev = y
        return y.astype(np.float32)
```

> 平滑系数、裁剪范围都属于**待官方接口确认**的参数，先留配置项，不写死。

## 7. 独立检验入口

按审查文档第四章约定，本阶段提供统一自证入口 `tools/verify_phase1.py`：

```bash
python3 tools/verify_phase1.py              # 人类可读结果，退出码 0/1/2
python3 tools/verify_phase1.py --json outputs/verify/phase1.json
```

| 检查 | 对应门禁 | 判定方式 | 无模型时可测 |
| --- | --- | --- | --- |
| `OBS_FIELDS` 各区间求和 = 1097 | G1-03 | `assert sum(lens) == 1097` | ✅ 纯 Python |
| 假输入切分后逐字段无重叠、无遗漏 | G1-03 | 区间并集覆盖 `range(1097)` | ✅ 纯 Python |
| 动作还原输出形状 `[1,225]`、dtype `float32` | G1-05 | 用 numpy 假动作输入 | ✅ 纯 Python |
| 值域裁剪生效（越界输入被夹到 `pose_min/max`） | G1-06 | 构造越界值断言 | ✅ 纯 Python |
| 平滑生效（`alpha` 在 [0.2,0.4]，输出连续帧差分下降） | G1-06 | 连续两帧输入对比 | ✅ 纯 Python |
| 镜像就绪、`--validate` 可运行 | G1-01 / G1-02 | 检测 `docker` 与镜像标签 | ❌ 需 Docker，否则记 `BLOCKED` |
| dummy 跑完 60s 产出 replay | G1-07 | 检查 replay 文件 | ❌ 需 Docker + GPU |
| 资源包、场景可加载 | G1-09 | 仿真启动日志 | ❌ 需 Docker + GPU |

**关键点**：G1-03/05/06 三条不依赖镜像、不依赖模型，只靠适配器代码即可判定，因此阶段一在"只有适配器、还没有网络"时就能完成大部分自证。缺 Docker 的条目必须记为 `BLOCKED`（退出码 2），**不得记为 PASS**（V-06）。
