# 验收流水线使用说明（给角色 A）

> 训练完把 `.pt` 交给流水线，30 秒得到「这个权重能不能用」。不用装环境、不用改代码、不用碰 docker。

## 1. 怎么跑

```bash
cd /home/yjh/H-Bot

# 快检（约 30 秒）：权重能不能导出、接口对不对、数值一致性
./scripts/accept.sh outputs/train/ckpt_0100.pt --skip-validate

# 完整验收（约 1 分钟）：再跑官方 validate 和完整链耗时
./scripts/accept.sh outputs/train/ckpt_0100.pt
```

- 权重路径给绝对路径最稳：`./scripts/accept.sh /home/yjh/H-Bot/outputs/train/ckpt_0100.pt`
- 版本号不用管：同一份权重自动复用已有版本号，新权重自动 +1；非要指定就加 `--version 7`。
- **不要加 `--matches`**：本地对战在本机 16GB 内存会 OOM，G3-07 由 B 在别的机器补。

## 2. 怎么看简报

跑完最后会打印两个路径：

- `outputs/review/brief_v{N}.md` —— 给人看的，手机也能读
- `outputs/review/brief_v{N}.json` —— 给脚本/B 看的

只看三处：

1. 第一行 **结论**；
2. 「八步流水线」表里的 **FAIL / BLOCKED** 行；
3. 「关键指标」表：大小、接口、一致性误差、耗时。

## 3. 怎么看结论

| 结论 | 含义 | 你要做什么 |
| --- | --- | --- |
| `PASS` | 全部通过 | 交给 B 走平台提交 |
| `PASS（受限）` | 只有 BLOCKED（基本就是 G3-07 没跑） | 直接交，不用管 |
| `FAIL` | 有硬性问题，简报「下一步」写明了哪一步 | 按下表处理 |

| 卡在哪 | 常见原因 | 怎么处理 |
| --- | --- | --- |
| 第 1 步 ckpt 体检 | 保存时缺 `policy` / `neutral` 键，或维度不是 1097→225 | 改训练保存逻辑，别动流水线 |
| 第 2 步 导出 | 目标版本文件已存在且内容不同 | 换版本号：`--version 8` |
| 第 3 步 结构/大小 | 超过 50MB、有动态轴、带 external data | 网络或输入形状改回固定 `[1,1097]` |
| 第 4 步 数值一致性 | torch 与 ONNX 输出差 > 1e-4 | 多半用了 ONNX 不支持的算子，找 B |
| 第 5 步 官方 validate | 平台侧不接受该模型 | 看 `outputs/eval/validate_v*.log` 里的 `error_code` |
| 第 6 步 耗时 | 完整链 > 10ms | 减层、减宽度，回到 4ms 量级再交 |

## 4. 三条规矩

1. 别改 `models/` 下已有文件——流水线按 sha256 认版本，改了会打架。
2. 别改 `tools/accept_ckpt.py` 里的阈值（50MB / 1e-4 / 10ms），那是提交门槛。
3. 看不懂结论就把 `outputs/review/brief_v{N}.json` 直接发给 B，别自己猜。
