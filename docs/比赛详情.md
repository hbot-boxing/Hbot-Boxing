## 一、赛题介绍

### 1. 赛题目标

本赛题考察人形机器人在动态对抗中完成进攻、防守和保持平衡的能力。

整体系统采用两层控制架构：

- **高层拳击策略**：由参赛队开发并提交。
- **下层运动控制器**：使用官方提供的 **HoloMotion 2.0** 模型，结构和参数固定，无需提交。

参赛队仅开发高层策略，根据仿真系统提供的自身状态和对手位置，生成**关键点轨迹序列**，并将其输入下层控制器，驱动机器人在仿真拳台中与对手进行比赛。

### 2. 参赛流程

```
获取官方资源，了解规则与接口
        ↓
开发与训练上层拳击策略
        ↓
导出 ONNX 模型
        ↓
本地校验与对战测试（可选，建议完成）
        ↓
提交模型并等待平台验证
        ↓
平台统一安排对战
        ↓
查看排名与回放，迭代策略
```

### 3. 机器人与观测

比赛采用配备拳套的 **Unitree G1** 人形机器人。上层策略所需的观测由仿真环境直接提供，主要包括：

| 观测类别 | 内容 |
| --- | --- |
| 自身状态 | 骨盆、双腕和双踝等身体点的位姿、速度及历史状态 |
| 对手信息 | 对手关键身体点相对自身的位置 |
| 比赛信息 | 剩余比赛时间和双方分差 |

上层策略输出未来短时间内的身体目标位姿，由主办方提供的 HoloMotion 2.0 下层控制器转换为机器人关节动作，并在仿真系统中完成状态迭代闭环。

**模型接口硬性要求**（提交前须满足，详见[四、1. 准备模型文件](#1-准备模型文件)）：

| 项目 | 要求 |
| --- | --- |
| 输入 | 单输入 `obs`，float32，形状 `[1,1097]` |
| 输出 | 单输出 `target_pose`，float32，形状 `[1,225]` |

> 具体接口定义与工具用法，请参阅下文「三、资源包下载」。平台验证时会检查模型格式、文件大小、接口与推理速度，上述维度、坐标系、观测字段及输出格式均须满足。

## 二、评分规则

### 1. 单场比赛成绩

每场比赛一回合，仿真时长上限 **60 秒**，在 **5 m × 5 m** 的场地内进行对战。机器人通过**有效手击**得分，时间结束时累计得分高者获胜，同分则判平局；出现击倒（KO）时提前结束比赛。具体判定规则如下：

| 项目 | 判定与得分 |
| --- | --- |
| 有效命中 | 手部接触对方头部或躯干，满足冲量要求后加 1 分；脚击不计分 |
| 冲量要求 | 每只手最近 20ms 内的法向冲量不低于 5 N·s |
| 重复命中 | 左右手分别计算，每只手两次计分至少间隔 200 ms；已计分的冲量不能重复使用 |
| 倒地判定 | 骨盆或躯干原点距拳台地面的高度严格低于 0.30 m |
| 击倒判定 | 连续倒地满 3 秒，对手加 1000 分并结束比赛 |

### 2. 排行榜成绩及晋级规则

- 排行榜使用 **Elo 等级分**，按照最后一日排行榜**前 16 名**晋级决赛。
- Elo 等级分每日重置为 **1500**，根据当日对战结果和对手的等级分更新。
- 等级分的变化**不受** KO 奖励分或单场比分差的影响。
- 每日提交截止（即当天北京时间 **18:00 的验证截止**）之后，平台统一安排对战。结果经人工复核后，**最早于次日北京时间 10 点公布**，届时可查看排名、比赛详情及回放。

## 四、提交指南

每天的提交时间为**北京时间 10:00 至 18:00**，上传及验证成功均须在 **18:00 前完成**。

为保证赛事公平，每队**每天最多尝试提交 3 次**，一次验证成功后当天不再接受新提交，**累计成功提交上限为 20 次**。建议先在本地完成模型校验和对战测试，再上传平台进行正式验证。

> 说明：详情页「各队伍正式评测次数限制为 5 次」写于**赛题一（指令跟随操作竞赛）**的提交指南，对应其远程模型服务评测；赛题二采用**模型文件上传验证**，适用上面的「每天 3 次尝试、累计 20 次成功提交」，不涉及该 5 次限制。

### 1. 准备模型文件

选手仅需提交上层策略的 **ONNX 文件**，所有权重须包含在文件内；HoloMotion 2.0 下层控制器由平台提供。

模型须满足以下要求：

| 项目 | 要求 |
| --- | --- |
| 输入 | 单输入 `obs`，float32，形状 `[1,1097]` |
| 输出 | 单输出 `target_pose`，float32，形状 `[1,225]` |
| 文件大小 | 严格小于 50,000,000 字节 |
| 推理要求 | 初赛使用 NVIDIA RTX 5090，单机器人完整推理链的平均耗时不超过 10 ms |

模型须同时满足维度、坐标系、观测字段及输出格式要求，推理耗时要求以在线平台结果为准，具体接口定义与工具用法见「三、资源包下载」部分。

### 2. 本地校验与对战

本地测试请使用[官方评测镜像](https://hub.docker.com/layers/horizonrobotics/holomotion/holoboxing-eval-v12-amd64)，并准备配备 NVIDIA GPU 的 Linux 环境，安装 Docker、NVIDIA 驱动及 NVIDIA Container Toolkit。

官方镜像支持两个功能：

- **单模型校验**：检查接口和运行要求。
- **双模型对战**：评估进攻、防守和平衡表现。

建议先完成校验，再运行对战并查看回放，检查策略的实际表现。

在 HoloMotion 仓库根目录依次执行以下命令，并将示例中的模型和回放路径替换为实际路径：

```bash
# 下载官方评测镜像。
export HOLOBOXING_IMAGE='horizonrobotics/holomotion:holoboxing-eval-v12-amd64'
docker pull "$HOLOBOXING_IMAGE"

# 校验单个模型。
./holoboxing/run.sh --validate models/red.onnx

# 运行双模型对战。
./holoboxing/run.sh --match models/red.onnx models/blue.onnx

# 查看对战生成的回放。
./holoboxing/run.sh --view results/match/replay.hdf5
```

补充说明：

- 也可通过 `docker load` 导入下载好的离线镜像包，并将 `HOLOBOXING_IMAGE` 设置为导入后的镜像标签或 ID。
- 已有测试结果不会被覆盖，重复测试时请通过 `--output` 指定新的输出路径。

### 3. 上传模型并等待验证

1. 完成平台注册、登录和队伍报名，进入拳击竞赛初赛页面。
2. 上传符合要求的 `.onnx` 文件，平台将检查模型格式、文件大小、接口和推理速度。
   - 验证期间，同一队伍不能提交其他模型。
3. 查看验证结果：
   - 验证成功后，平台统一安排对战。
   - 验证失败则根据检查结果修正模型，并在提交次数和时间限制内重新提交。
4. 对战结果公开后，在平台查看成绩和回放。

注意事项：

- **上传并通过验证才算提交成功**，两者均须在当天北京时间 18:00 前完成，请为排队和验证留出时间。
- 模型验证失败或超过截止时间会消耗尝试次数；平台故障按规则退还次数。
- 平台使用队伍**最新验证成功的模型**参赛。当日没有新模型通过验证时，沿用之前的成功模型；失败或仍在验证的新模型不会替换它。

### 4. 查看成绩与回放

- 结果经人工复核后，**最早于次日北京时间 10 点公开**。
- 公开后，可以在平台查看排行榜、比赛详情和比分，并下载 **HDF5 轨迹文件**。
- HDF5 是保存结构化数据的文件格式，回放工具支持播放、进度跳转、事件查看和 MP4 导出。
- 导出视频建议使用兼容的 **Chrome 或 Edge**，并在 HTTPS 或 localhost 环境中操作。导出过程中请保持页面可见，等待生成完成；声音开关会同时影响回放和导出视频。

## 五、常见 Q&A

**Q1：需要上传模型，还是在自己的服务器上运行？**

拳击竞赛采用**模型文件上传**方式，参赛队只需提交上层策略的 ONNX 文件，无需提供远程模型服务，也无需通过 WebSocket 连接平台。HoloMotion 2.0 下层控制器由主办方统一提供。

**Q2：文件恰好 50 MB 可以吗？**

不可以。模型文件必须**严格小于 50,000,000 字节**，不接受恰好等于上限的文件。这里按十进制字节数计算，不是 50 MiB。

**Q3：本地校验通过，是否说明模型已经具备比赛能力？**

不能。本地校验不评价策略的对抗能力，实际表现需通过对战和回放分析。普通校验不测量完整推理链时延，测时需添加 `--benchmark`；本地校验通过也不能替代平台验证。

**Q4：上层模型单独耗时低于 10 ms 就能通过吗？**

不能仅凭这一结果判断。10 ms 的上限针对**上层策略与下层控制器组成的完整推理链平均耗时**，以官方 RTX 5090 实测结果为准。

**Q5：本地只有 RTX 4090，可以测试吗？**

可以进行模型校验、对战和时延测试，但 RTX 4090 的测时结果不能直接作为初赛验收依据，是否达标以官方 RTX 5090 实测结果为准。

**Q6：17:59 上传完成，18:01 验证成功，算当天提交成功吗？**

不算。上传和验证成功均须在当天北京时间 18:00 前完成，超时会消耗一次尝试次数。当日没有新模型在截止前通过验证时，平台沿用此前验证成功的模型。

**Q7：持续接触对手能重复得分吗？**

可以，无需先与对手分离。左右手分别计分，每次须满足有效接触条件、重新积累达到要求的冲量，并与该手上次计分至少间隔 200 ms。已计分的冲量不能重复使用。

**Q8：身体倾斜或高度等于 0.30 m 算倒地吗？**

仅身体倾斜不算倒地。骨盆或躯干原点距拳台地面的高度**严格低于 0.30 m** 时判为倒地，等于阈值时不算。连续倒地满 3 秒才判为击倒（KO）。

**Q9：双方同时被击倒（KO），如何判定胜负？**

双方同时满足连续倒地满 3 秒的条件时判为**平局**，不受当前比分影响；仅同时倒地、尚未满足 KO 条件时，比赛继续。

**Q10：为什么晚上看不到当天积分？**

当天结果需要先经过人工复核，最早于次日北京时间 10 点公开。请在公开后查看积分、比赛记录和回放。

**Q11：本地对战会更新官方排行榜吗？**

不会。本地工具只用于调试和自测，官方成绩以平台组织的比赛结果为准。
