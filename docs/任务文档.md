## 一、项目概述与目标

### 1.1 赛题

**赛题二：拳击竞赛**（H-Bot 地平线机甲巅峰赛）

### 1.2 目标

开发能在端侧算力约束下，基于 HoloMotion 运动控制基座、在动态对抗中完成**进攻、防守和保持平衡**的上层拳击策略模型。

最终产物：一个 ONNX 格式的策略模型文件（所有权重内嵌）。

### 1.3 核心指标

| 指标 | 目标 |
| --- | --- |
| 排行榜排名 | 前 **16 名**晋级决赛 |
| Elo 等级分 | 每日从 **1500** 起步，通过战胜高水平对手提升 |
| 单机器人推理耗时 | 完整推理链（上层 + HoloMotion 2.0）平均 ≤ **10 ms**，以 RTX 5090 实测为准 |
| 模型文件大小 | 严格 < **50,000,000 字节**（十进制） |
| 每日最少比赛场次 | ≥ **15 场** |
| 累计成功提交上限 | **20 次** |

### 1.4 赛程

| 时间 | 事项 |
| --- | --- |
| 2026.10.22 | 报名开启 |
| 2026.12.03 | 初赛提交截止（报名截止） |
| 2026.12.10 | 初赛结果公布，决赛开启 |
| 2027.01.07 | 决赛提交截止 |
| 2027.01.14 | 最终获奖结果公示 |

## 二、任务分解

### 阶段 1：环境搭建 & 接口对齐

**目标**：具备本地开发、训练、校验与对战的全部工具链。

#### 1.1 硬件准备

- [ ] 配备 **NVIDIA GPU** 的 Linux 环境
- [ ] 安装 Docker、NVIDIA 驱动、NVIDIA Container Toolkit

#### 1.2 拉取官方资源

- [ ] 拉取评测镜像
  ```bash
  docker pull horizonrobotics/holomotion:holoboxing-eval-v12-amd64
  ```
- [ ] 下载拳击机器人与场景资源包（Hugging Face）
- [ ] Clone HoloMotion 仓库，阅读 `holoboxing/` 下的训练教程、模型接口文档

#### 1.3 接口对齐

- [ ] 确认观测输入 `obs` 的 1097 维字段语义与坐标系
- [ ] 确认输出 `target_pose` 的 225 维字段语义与关节/关键点映射
- [ ] 编写观测解析与动作还原的工具代码

**交付物**：可运行的基础脚本（校验镜像 + 观测/动作解析工具）

---

### 阶段 2：策略模型设计与训练

**目标**：训练出一个在本地对战中具备基本攻防能力的策略模型。

#### 2.1 网络设计

- [ ] 确定模型架构（MLP / Transformer / 混合，需考虑 ≤ 10ms 推理约束）
- [ ] 参数量估算（满足 < 50MB 导出）

#### 2.2 训练

- [ ] 准备训练环境与数据集
- [ ] 设计奖励函数：
  - 进攻奖励：有效命中
  - 防守奖励：避免被命中、维持站位
  - 平衡奖励：防止倒地
  - 比赛奖励：比分优势、KO
- [ ] 实现训练循环（RL / IL / 混合）
- [ ] 阶段性 checkpoint 保存

#### 2.3 本地自测

- [ ] 使用官方镜像进行双模型对战测试
- [ ] 分析回放，定位策略缺陷
- [ ] 迭代优化

**交付物**：训练代码、checkpoint 权重、本地对战记录

---

### 阶段 3：ONNX 导出与本地校验

**目标**：导出的 ONNX 文件通过本地校验，推理耗时初步达标。

#### 3.1 ONNX 导出

- [ ] 将训练权重导出为 ONNX，内嵌所有权重
- [ ] 验证：
  - 输入 `obs` float32 `[1,1097]`
  - 输出 `target_pose` float32 `[1,225]`
  - 文件大小 < 50,000,000 字节

#### 3.2 本地校验

```bash
./holoboxing/run.sh --validate models/my_model.onnx
```

- [ ] 校验通过（格式、接口）
- [ ] `--benchmark` 测时，初步评估推理耗时

**注意**：本地 RTX 4090 测时结果不能直接作为初赛验收依据。

#### 3.3 本地对战验证

```bash
./holoboxing/run.sh --match models/my_model.onnx models/opponent.onnx
./holoboxing/run.sh --view results/match/replay.hdf5
```

- [ ] 至少完成多场本地对战
- [ ] 回放分析：进攻效率、防守漏洞、倒地倾向
- [ ] 根据分析结果迭代模型

**交付物**：ONNX 模型文件、本地校验结果、对战回放分析报告

---

### 阶段 4：平台提交 & 对战迭代

**目标**：在每日提交窗口内完成验证，通过平台对战提升 Elo 排名。

#### 4.1 提交节奏

| 约束 | 说明 |
| --- | --- |
| 提交窗口 | 每日 **10:00–18:00**（北京时间） |
| 每日尝试 | ≤ **3 次**，一次成功后当天锁定 |
| 累计成功 | ≤ **20 次** |
| 对战安排 | **18:00 验证截止后**平台统一安排 |
| 结果公布 | 最早**次日 10:00**（人工复核后） |

#### 4.2 每次提交前 Checklist

- [ ] ONNX 文件满足接口、大小、格式要求
- [ ] 本地校验通过
- [ ] 本地对战表现有提升（或至少不退化）
- [ ] 预留验证排队时间（**不要卡 18:00 截止**）

#### 4.3 迭代策略

- [ ] 每日查看前一日对战结果与回放
- [ ] 分析 Elo 变化趋势、胜负原因
- [ ] 针对性优化策略后再提交
- [ ] 关注排行榜上高 Elo 对手的打法特征

**交付物**：每次提交的 ONNX 文件、对战结果复盘记录

## 四、约束与验收标准

### 4.1 模型格式

| 项目 | 标准 | 不通过后果 |
| --- | --- | --- |
| 格式 | ONNX | 无法提交 |
| 输入 | `obs` float32 `[1,1097]` | 推理失败 |
| 输出 | `target_pose` float32 `[1,225]` | 推理失败 |
| 文件大小 | < 50,000,000 字节（不等号严格） | 上传被拒 |
| 推理耗时 | 完整链 ≤ 10ms（RTX 5090） | 验证失败 |

### 4.2 合规

- 评测阶段**不得引入独立的外部大模型**进行任务规划、指令分解或多模型决策编排
- 赛事方有权对模型及推理链路进行核验

## 五、风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| ONNX 大小刚好 50MB 被拒 | 浪费一次提交尝试 | 导出前预留 buffer，严格检查字节数 |
| 18:00 前未完成验证 | 消耗尝试次数，当日无法参赛 | 不晚于 17:00 提交，预留排队时间 |
| 本地 4090 测时通过但 5090 不达标 | 验证失败 | 早日在平台完成一次验证，确认实际耗时；模型留推理耗时余量 |
| 策略过度拟合自测对手 | 平台对战中 Elo 不佳 | 多对手交叉测试；利用回放分析平台对手特征 |
| 模型验证失败超过尝试次数 | 当天无法再提交 | 本地充分校验后提交；预留至少 1 次重试机会 |
| 决赛端侧设备适配困难 | 决赛成绩受影响 | 关注官方发布的端侧部署文档；提前做模型轻量化 |
| 每日最少 15 场未达标 | Elo 更新不充分 | 确保每天在截止前成功提交模型 |
