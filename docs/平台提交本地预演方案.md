# 平台提交本地预演方案

> 目的：在正式提交前把「人、账号、网络、文件、记录、时间」六个环节各演练一遍，做到正式提交时只需点一次按钮。
> 原则：**预演全程不消耗尝试次数**——不点最终提交、不在提交页选真实文件上传、任何看到的状态都先截图。

## 1. 环境侧（可自动化，已实测）

| 检查项 | 命令 | 2026-11-04 实测 | 判据 |
| --- | --- | --- | --- |
| 站点可达 | `curl -sS -o /dev/null -w '%{http_code} %{time_ttfb}s' https://hbot-competition.horizon.auto/` | `200`，TTFB 0.38s | 200 且 < 2s |
| DNS / TLS | 同上（`time_namelookup` / `time_appconnect`） | 0.102s / 0.329s | 无超时、无证书错误 |
| 时钟同步 | `timedatectl` | `Asia/Shanghai`，`synchronized: yes`，NTP active | 时区 +0800 且已同步 |
| 上行带宽 | 浏览器上传不限速验证，或 `speedtest-cli --simple` | 未测（见下） | 5MB 文件 < 30s |
| 浏览器 | Chrome/Edge，无拦截类扩展，省电模式关闭 | 待确认 | 能正常选文件并看到进度 |
| 上传方式 | 平台是「选文件→点提交」还是「选文件即上传」 | **待确认**（决定预演能否安全进行） | 见第 8 节 |

`speedtest-cli` 未安装，且不建议为测速向第三方上传文件；改用「把 5MB 的 ONNX 拖进平台上传框，看进度条速度后立即取消」这种只读演练（仅当平台是两段式提交才允许做）。

## 2. 账号与页面状态（只在页面观察，不做提交）

| 项 | 预演动作 | 判据 |
| --- | --- | --- |
| 登录 | 打开站点 → 登录 → 进入「拳击竞赛初赛」页面 | 能看到提交入口且无 401/失效提示 |
| 队伍信息 | 查看队名、成员、队长身份 | 信息正确；确认**是否只有队长能提交** |
| 当前验证中任务 | 进提交页看是否已有任务在验证 | 显示「无验证中任务」（有则当天不能再传） |
| 提交次数余额 | 看页面显示的当日剩余次数 | 与记录表账本一致 |
| 验证结果页 | 找到「验证成功/失败」展示位置 | 知道从哪看结果 |
| 排行榜/回放 | 找到次日成绩与 HDF5 回放入口 | 能定位，无需下载 |
| 故障申诉入口 | 找客服/工单/官方飞书群入口 | 有一条可用通道 |

## 3. 提交物与记录（正式提交前的准备）

1. 候选文件命名统一：`policy_v{N}_{YYYYMMDD}.onnx`；复制一份到 `submit/` 目录（避免改坏 `models/` 原文件）。
2. 跑一次验收，简报必须满足：G3-01/02/03/04/05/08 PASS（G3-06 见内存条件，G3-07 允许 BLOCKED）。
3. 记录 sha256 与字节数：`sha256sum submit/*.onnx && stat -c '%s %n' submit/*.onnx`。
4. 记录表模板（每次尝试一行，提交前先填前 8 列，提交后补后 4 列）：

| version | date | sha256 | size_bytes | mean_ms | validate | upload_time | attempt_no | platform_status | failure_reason | elo | replay_path |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| v1 | 2026-11-04 | `caad2aea…` | 2359996 | —（本机 8GB 限制未测） | PASS | — | — | — | — | — | — |

5. 次数账本：`当日已用 0/3`、`累计成功 0/20`，每次提交后立即更新。

## 4. 预演动作（八个，总耗时约 20 分钟）

| # | 动作 | 预期 | 判据 | 耗时 |
| --- | --- | --- | --- | --- |
| R-01 | 跑 `timedatectl` + `curl` 站点探测 | 时区 +0800、站点 200 | 见第 1 节表 | 1 min |
| R-02 | 登录并进入初赛页，检查队伍与「验证中」状态 | 无验证中任务、次数 3/3 | 截图两张 | 3 min |
| R-03 | 找到提交按钮、文件选择框、提交确认按钮（**不点**） | 清楚交互是两段式还是一段式 | 记录结论 | 2 min |
| R-04 | 演练上传：拖入一个 1KB 的假 `.onnx`，看校验报错文案后**立即取消**（仅两段式平台可做） | 得到「格式/接口错误」的文案样式 | 文案截图；未产生提交 | 3 min |
| R-05 | 计时演练：从「点选择文件」到「点提交」走一遍空流程（不选真实文件则跳过计时） | 总操作 ≤ 3 分钟 | 用秒表记录 | 2 min |
| R-06 | 演练失败分支：找到「验证失败」在页面的展示位置与申诉入口 | 两条路径都定位到 | 截图 | 3 min |
| R-07 | 演练结果确认：找「验证成功」标记、次日 10:00 的成绩页、回放入口 | 三处都定位到 | 截图 | 3 min |
| R-08 | 把记录表按模板填好一行（用真实候选文件名与 sha） | 12 列无空缺（后 4 列留空） | 表格截图 | 3 min |

> R-04 是唯一有风险的演练：**如果平台是「选文件即上传」，跳过 R-04**，改用「上传一个明显超限的 60MB 假文件」也不安全，直接放弃这一项并在第 8 节记录「交互为一段式」。

## 5. 正式提交 SOP（时间轴）

| 时间 | 动作 | 输出 |
| --- | --- | --- |
| T-1 09:30 | 关闭浏览器大页面/IM，腾内存；确认 `models/` 候选未被改动 | `free -m` ≥ 8GB（若还要跑测速） |
| T-1 09:50 | 复跑验收（快检 30s + 需要的完整项），确认简报 PASS | `outputs/review/brief_v{N}.md` |
| T-1 09:55 | 记录 sha256、字节数，填记录表前 8 列 | 记录行 |
| T 10:00 | 登录 → 确认无验证中任务 → 上传 `submit/policy_v{N}_*.onnx` | 上传完成提示 |
| T 10:00–10:10 | 点提交 → 拿到「已提交/验证中」状态，记录 `upload_time`、`attempt_no` | 状态截图 |
| T 10:10–17:00 | 每 30 分钟看一次验证状态；**17:00 前必须已验证成功** | 状态截图 |
| T 17:00 | 若仍在排队且未验证成功：接受本次失败、等次日 | 记录 `failure_reason=queue_timeout` |
| T+1 10:00 | 查 Elo、名次、比赛详情，下载 HDF5 回放 | 更新记录表 `elo`、`replay_path` |

## 6. 三种失败分支的处置（当天内可救、可放弃）

| 原因 | 现象 | 当天动作 |
| --- | --- | --- |
| 接口/格式 | 提示输入输出名、维度、dtype 不符 | 当天无法改模型前提下：放弃，次日修（本质是本地 G3-01/02 没跑） |
| 文件超限 | 提示大小超限 | 同上；本地 G3-03 已兜住，不该出现 |
| 推理超时 | 提示耗时超限 | 若本地 G3-06 缺失证据（内存受限），优先换机器补测再提交，不要当天硬试 |
| 平台故障 | 页面报错/上传中断/长时间验证中 | **截图 + 记时间**，走申诉退次数；不算模型问题 |
| 排队超时 | 17:59 上传、18:01 才成功 | 记 `queue_timeout`，当天次数已消耗 |

## 7. 预演验收（三态）

| 编号 | 项 | 判据 |
| --- | --- | --- |
| R1 | 网络与时钟 | 站点 200、TTFB < 2s、时区 +0800 且 NTP 同步 → PASS |
| R2 | 账号与队伍 | 登录正常、队伍信息正确、无验证中任务 → PASS |
| R3 | 提交交互已摸清 | 明确两段式/一段式 → PASS；未知 → BLOCKED |
| R4 | 上传报错文案已记录 | 有截图且未消耗次数 → PASS；一段式平台 → BLOCKED |
| R5 | 操作计时 | 全流程 ≤ 3 分钟 → PASS |
| R6 | 失败与申诉路径 | 两处都定位到 → PASS |
| R7 | 结果与回放入口 | 三处都定位到 → PASS |
| R8 | 记录表就绪 | 12 列模板已填首行 → PASS |

八项全部 PASS 才视为「预演完成」；任一 BLOCKED 必须在正式提交前补齐，否则视为未预演。

## 8. 已知不确定项（需要真人上平台确认）

1. 平台提交是「选文件→点提交」还是「选文件即上传」——决定 R-04/R-05 能否执行。
2. 仅队长可提交还是队员皆可。
3. 上传大小/格式的前端校验在选文件时还是提交后。
4. 「验证中」任务是否跨天保留（影响次日 10:00 前能否上传）。
5. 次数退还的申诉渠道与所需材料（截图字段、工单模板）。
